     1→     1→============================================================
     2→     2→MASTER IMPLEMENTATION PLAN
     3→     3→CLOUD-NATIVE VIDEO SHARING PLATFORM
     4→     4→============================================================
     5→     5→
     6→     6→You are implementing a production-quality, cloud-native web application
     7→     7→that acts as a video-sharing platform conceptually similar to TikTok.
     8→     8→
     9→     9→This is an academic/project implementation, but it must be designed using
    10→    10→real production-oriented architecture rather than a frontend-only mockup.
    11→    11→
    12→    12→The application must use Microsoft Azure as the primary cloud platform.
    13→    13→
    14→    14→============================================================
    15→    15→CRITICAL DEVELOPMENT RULES
    16→    16→============================================================
    17→    17→
    18→    18→1. DO NOT immediately start writing the UI.
    19→    19→
    20→    20→2. DO NOT create a mock frontend that pretends the backend exists.
    21→    21→
    22→    22→3. DO NOT store video files inside the relational database.
    23→    23→
    24→    24→4. DO NOT put Azure credentials, storage account keys, database passwords,
    25→    25→   client secrets, or other secrets inside frontend code.
    26→    26→
    27→    27→5. DO NOT allow consumers to upload videos.
    28→    28→
    29→    29→6. DO NOT rely only on frontend UI restrictions for authorization.
    30→    30→   All permissions must also be enforced server-side.
    31→    31→
    32→    32→7. DO NOT expose Azure Blob Storage credentials to the browser.
    33→    33→
    34→    34→8. Use secure, short-lived upload authorization for direct browser-to-Blob
    35→    35→   uploads.
    36→    36→
    37→    37→9. Use exact and consistent terminology throughout the entire application.
    38→    38→
    39→    39→10. Do not invent functionality that has not been requested.
    40→    40→
    41→    41→11. Do not replace the requested cloud architecture with local storage,
    42→    42→    mock APIs, JSON files, or in-memory data.
    43→    43→
    44→    44→12. Do not skip database design, API design, authentication,
    45→    45→    authorization, security, validation, error handling, testing,
    46→    46→    deployment, or documentation.
    47→    47→
    48→    48→13. Before implementing each phase, verify that the previous phase is
    49→    49→    complete and working.
    50→    50→
    51→    51→14. Never silently change the architecture.
    52→    52→
    53→    53→15. If a technical decision is necessary, choose the simplest production-
    54→    54→    appropriate solution that satisfies the requirements and document it.
