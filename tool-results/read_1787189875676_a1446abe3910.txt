     1→============================================================
     2→MASTER IMPLEMENTATION PLAN
     3→CLOUD-NATIVE VIDEO SHARING PLATFORM
     4→============================================================
     5→
     6→You are implementing a production-quality, cloud-native web application
     7→that acts as a video-sharing platform conceptually similar to TikTok.
     8→
     9→This is an academic/project implementation, but it must be designed using
    10→real production-oriented architecture rather than a frontend-only mockup.
    11→
    12→The application must use Microsoft Azure as the primary cloud platform.
    13→
    14→============================================================
    15→CRITICAL DEVELOPMENT RULES
    16→============================================================
    17→
    18→1. DO NOT immediately start writing the UI.
    19→
    20→2. DO NOT create a mock frontend that pretends the backend exists.
    21→
    22→3. DO NOT store video files inside the relational database.
    23→
    24→4. DO NOT put Azure credentials, storage account keys, database passwords,
    25→   client secrets, or other secrets inside frontend code.
    26→
    27→5. DO NOT allow consumers to upload videos.
    28→
    29→6. DO NOT rely only on frontend UI restrictions for authorization.
    30→   All permissions must also be enforced server-side.
    31→
    32→7. DO NOT expose Azure Blob Storage credentials to the browser.
    33→
    34→8. Use secure, short-lived upload authorization for direct browser-to-Blob
    35→   uploads.
    36→
    37→9. Use exact and consistent terminology throughout the entire application.
    38→
    39→10. Do not invent functionality that has not been requested.
    40→
    41→11. Do not replace the requested cloud architecture with local storage,
    42→    mock APIs, JSON files, or in-memory data.
    43→
    44→12. Do not skip database design, API design, authentication,
    45→    authorization, security, validation, error handling, testing,
    46→    deployment, or documentation.
    47→
    48→13. Before implementing each phase, verify that the previous phase is
    49→    complete and working.
    50→
    51→14. Never silently change the architecture.
    52→
    53→15. If a technical decision is necessary, choose the simplest production-
    54→    appropriate solution that satisfies the requirements and document it.
    55→

   400→Moderate content   YES      NO        NO
